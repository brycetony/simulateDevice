# 流水线 Workflow 规格：域冷启动前半程（钉基线 → 考古 → 三视角 → 裁决①票拟）

- 来源：AGENTS.md §7 需求全流程流水线（T-003 落规）的阶段二固化（T-005）；格式从 T-004 AUTH 首飞实战反推。
- 边界（owner 裁决 2026-11-09）：**编排到「裁决材料生成」为止**——人工批量裁决是天然断点，
  裁决后的契约回填与实现阶段仍由会话驱动（实现段编排另卡）。
  （v2 注记 2026-11-11：对实现段的外边界不变；workflow **内部**编排自 v2 起止于三视角交付，
  「裁决材料生成」中的汇总出票移至调用会话执行——见下方 v2 修订与阶段 3。）
- 调用方式：一次调用，输入 = 目标域 + 一句话需求 + 仓库路径。
- **v2 修订（2026-11-11；T-005 §8 复盘两项 + T-006 基线漂移教训一项，经 T-006 实战验证后落地）**：workflow 编排收窄为
  钉基线 + 考古 + 三视角交付（一张材料卡）；**汇总出票回归调用会话执行**——v1 曾编排为
  workflow 内汇总子代理（实测单点 1.22M tokens，且 T-006 实战证明调用会话汇总质量不降）。
  实现见全局 `domain-coldstart`（重存覆盖）。

## 阶段 0：钉基线（v2 新增）

起跑时 `git rev-parse HEAD` + `--abbrev-ref HEAD` + `status --short` 实测一次，
把「仓库 @ hash（分支，工作树状态）」注入考古与三视角全部 prompt——行号引用自此有唯一
基准；实读状态与基线不符必须明说，禁止静默换基线。教训出处：T-005 演练的事实清单记
`t005-pipeline-stage2@adae6f8` 与实测 master 不符，T-006 归档时人工补钉 3df7108→d166371。

## 阶段 1：考古侦察（只读）

| 项 | 定义 |
|----|------|
| 输入 | 域范围（视图/模块清单）、需求一句话 |
| 执行者 | 只读侦察 agent（Explore 类） |
| 动作 | 通读相关文件、git 历史、既有契约/故障库关联、外部依赖（后端 API 形状从调用侧推断） |
| 输出 | **事实清单**：候选约束表（现状描述 + `文件:行号` 证据）/ 异常可疑清单 / 未决问题原料 / 外部依赖表。只列事实不下结论；找不到的明说"未找到"，禁止推测填充 |
| 禁止 | 修改任何文件；出现 [确认] 状态 |
| 基准耗时 | 手工口径：考古+报告起草合并 40m（T-004 §6 实测）；workflow 编排后的纯侦察段以演练实测为准（见 T-005 §6） |

## 阶段 2：三视角并行讨论（3 路并发，互不等待）

| 视角 | 输入 | 交付 |
|------|------|------|
| 架构 | 事实清单 + 草稿卡 + 既有域范式 | 契约切分方案（条目收敛草案）/ 纯函数抽取边界 / 修复方案选项+推荐 / 分歧与不确定项 |
| 测试 | 事实清单 + 既有测试范式 | 逐条可执行验收判据（给定输入→必然断言，含边界）/ 可测性障碍与依赖注入方案 / 测试文件规划 / 防同源约束清单 |
| 红队 | 事实清单 + 既有契约原则 + 历史故障模式 | 攻击面/缺陷链推演（可修性分级 FR/FM/BE）/ 三缺陷模式（弱随机·静默失败·覆盖缺失）同类遗漏扫描 / 新增候选约束与缺陷（续编号）/ 风险分级 P0-P2 |

共同规矩：只读不改；产出喂裁决不为求共识；每条带证据。
**交付压缩铁律（v2）**：紧凑表格；禁止重抄事实清单原文，引用其编号（C/D/Q）；每条一句话；
deliverable 总长 ≤4000 字，分歧每条 ≤60 字——喂给汇总的材料越短，汇总与复核越便宜
（v1 三视角长交付是汇总子代理 1.22M tokens 的主要输入）。

## 阶段 3：汇总出票（主会话；v2 起 workflow 不编排此段）

workflow 终点 = 发布「冷启动材料」卡（事实清单 + 三视角交付 + 基线），返回值指明移交。
调用会话接手：

1. 合并三方产出：新候选并入事实清单（C/D/S 续编号）；分歧清单 F 项逐条附双方立场与推荐。
2. 落档：RESEARCH 报告（`docs/tasks/RESEARCH-<域>-<日期>.md`，模板 RESEARCH-template）+
   草稿卡（T-template，§3 填分歧清单）。
3. 产出**裁决①票拟包**：约束批量确认（附收敛方案）/ 缺陷修复范围（附推荐包）/
   安全分流（附推荐）/ 三栏草案 / OPEN 与后端必答清单——一次批量，每项有推荐，人可整包批。

## 断点：裁决①（人）

人批量批红（实测 ~10 分钟"全推荐"或逐项点名）。裁决后回到会话驱动：
契约回填 → 建卡完成 → 界面设计判定（§7）→ 拆批实现。

## 质量红线（各阶段通用）

- 证据必须 `文件:行号` / commit / 测试名；推测必须标注且不得作为实现依据。
- OPEN 条目任何阶段禁止自行实现（AGENTS.md §1）。
- 高风险类变更（§3）不适用三视角豁免——本 workflow 默认全跑三视角，豁免由人显式声明。
